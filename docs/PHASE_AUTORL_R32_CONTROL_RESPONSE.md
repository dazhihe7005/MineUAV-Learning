# AUTORL-R32：既有闭环控制响应审计

## 【1】阶段目标

在不新增物理运行或训练的条件下，核对R27成功先验与R30/R31超时轨迹中的命令、PI积分、姿态和实际运动时序，确定哪些证据支持、哪些仍缺失。

## 【2】技术背景

R31已发布24e8b51b94f0ce520ed150459cff3d81dee0427a：固定D=.3两例0/2成功，终点速度.434/.448m/s，高于R30的.345/.350。不能因此盲目增大反馈或认定PI实现错误。R27先验曾两例停稳，但模型与Yaw干预不同，不能把三组当作只改变一个变量的控制实验。

## 【3】系统架构

已冻结报告/raw SHA → 既有完整trace算术验证 → control_response_audit.py纯标准库有限差分/姿态/PI贡献/固定相关网格 → 三张真实旧数据图与报告。没有模型加载、推理、mj_step、扫描、episode或优化器。

## 【4】代码实现

response_samples严格要求连续20tick/40ms区间，检查有限向量、单位四元数与真实速度；加速度为(v_post−v_pre)/.04而非伪造IMU。lag_alignment仅允许正偏移1..25，少于8对或零方差返回NOT_OBSERVABLE/None，不填0冒充结果。summarize_response只报告描述性指标，显式motor_saturation=NOT_OBSERVABLE、causal_root_cause=UNVERIFIED。五个测试实际缺接口RED→GREEN，合成正弦仅验证算术，不是实测点云或新轨迹。

## 【5】算法原理与时间

500Hz物理、100Hz控制、25Hz策略的源代码表明每个完整20tick区间在0/5/10/15tick调用控制，最后请求来自post−.01s；40ms速度差是整个区间平均，放在中点post−.02s。固定[3,7]s窗口，lag L=1..25配对请求和后续区间平均，样本偏移.04L−.01=.03..99s；Pearson最大值只是预先冻结25点中的描述性选择，不是延迟实测、因果辨识或稳定裕度。

自身状态反例仅为源码数学推导：相同pose/velocity/heading/瞬时冻结LiDAR及动作，可有不同PI积分记忆或bodyrates；未限幅时积分差使请求加速度差[.5,.5,.8]·ΔI，姿态PD也显式使用bodyrates。因此即时7D+heading未完整暴露内部动力学状态；当前LiDAR可提供几何线索，但不能把此反例当作已测得完全相同full observation的两状态，或宣称这就是学习失败唯一原因。

## 【8】问题分析

CONFIRMED：不同采样时刻、真实PI记忆/角速度存在、特征没有直接暴露这些内部量、实际完整trace与终止一致。SUSPECTED：策略映射与内环动态、观测记忆不足、短距离课程造成原距离能力遗忘，需独立实验区分。UNVERIFIED：唯一故障原因、真实控制延迟、电机饱和、加入历史/自身姿态是否改善学习；不据相关性宣告控制器Bug。
