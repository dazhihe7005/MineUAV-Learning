# OPS-02：便携回归与版本化科研管理

## 【1】阶段目标

消除旧LiDAR测试对易丢失/tmp副本的依赖；以独立版本登记新Level0/1任务和交付名单，不篡改V1、不提升训练权限。

## 【2】技术背景

OPS-01的doctor已使用持久依赖，但17份LiDAR测试仍指定临时副本，导致测试夹具与Python导入来源混用。V1冻结了管理源码和提交名单，不能直接修改V1协议SHA来发布新功能。

## 【3】系统架构

`research_regression.upstream`统一解析持久依赖并保留提交/pattern身份验证；`research_regression.run`使用冻结解释器与一致PYTHONPATH执行原有无优化器回归。`researchctl-v2 → registration → manager → execution / publication`使用原V1 flock和存储工具，但读写独立版本目录。V1代码及本地历史只读。

## 【4】代码实现

17份测试只替换上游路径来源，未改扫描器、奖励、动力学或训练算法。新代码位于 `research_regression/`、`research_ops_v2/`、`researchctl-v2`，测试位于 `tests/research_ops_v2/`。V2清单：`mujoco/reports/research_operations_v2_registration.json`。独立清单明确任务类型、参数、资源预算、源码、交付列表及17份测试before/after SHA。

原V1必需的 `recover` 在preflight中按原语义更新过本地状态和公开快照；执行前已另存完整原文件及manifest，路径见机器报告。这不是V2迁移覆盖V1。迁移后原V1核心文件逐字节保持。

## 【5】实现原理

采用校验和、原子写入、内核flock及显式父版本链。状态丢失/损坏不能用公开文档猜测恢复；完整marker只证明对应任务，不自动证明阶段完成。停止使用进程组，避免仅结束worker而留下编译器。旧版本状态与源码归档不可被新清单重写。Git从已经核验的发布锚点审计未推历史，防止登记时提前提交敏感文件后跳过检查。

## 【6】验证协议

无训练随机种子或timesteps，授权与消耗均0。使用单CPU、受限真实MuJoCo历史回归、标准库单测、临时Git仓库及模拟进程。旧/tmp目录保持原样，历史回归用显式Python审计钩子模拟“旧依赖不可访问”；不是物理删除，也不是隐藏替换scanner。实际导入目录、Git提交和patternSHA写入原始结果。

## 【7】结果与证据

便携相关历史回归：885 PASS、15 DESELECTED、0 FAIL、0 SKIP，2项已知警告；耗时124.83秒，峰值RSS1953.40MiB，采样最低MemAvailable7992.40MiB，optimizer调用0。15项排除逐项保存在机器报告关联证据，包含需要优化器及旧冻结身份断言的测试，不能称全仓测试。

V1管理回归：49 PASS。V2新增34项测试覆盖登记、迁移失败保护、原状态保留、源码强制覆盖、进程锁/停止/恢复、预算拒绝、Git提交及同步失败重试等；0失败、0跳过。包括启动握手前主管崩溃、attempt后状态写失败、进程组守护超时的真实模拟进程验证。最终实际迁移与独立复审结果见本阶段机器报告；不能把临时仓库测试当成真实GitHub发布已完成。

首次迁移前回归收集出现3个future import顺序错误，保留失败记录，修复后才得到885通过；没有将首次失败覆盖为成功。初审NO_GO发现的重要问题修复并增加回归，最终审查身份单独记录。

## 【8】问题分析

CONFIRMED：混合硬编码路径是已知回归不便携的来源；持久源码与实际导入一致后相关回归通过。CONFIRMED：原V1不具备新阶段登记能力，V2采用新协议而非重新初始化V1。UNVERIFIED：实际断电、磁盘硬件故障及未来所有依赖变化，不由模拟重启测试证明。

## 【9】局限性

未实际重启电脑。没有后台AI、开机服务、分布式平台或数据库。规则敏感信息检查不替代人工审阅。本机同权限恶意进程不在安全隔离承诺内。历史OpenCV/NumPy ABI和Matplotlib/Gymnasium警告仍保留，未升级全局依赖。仅相关选定回归；无全仓测试或飞行认证。没有实现EXACT_RESUME、BOUNDARY_RESUME或训练预算授权功能。
